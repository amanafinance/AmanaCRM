# Настройка Amana CRM

Все шаги бесплатные, тариф Firebase Spark (бесплатный) подходит.

## 1. Роли и правила доступа (обязательно по порядку!)

Правила из `firestore.rules` пускают в базу только тех, кто записан в коллекцию `users`.
Если опубликовать правила раньше шага 1.2, вы сами потеряете доступ (это исправляется откатом правил в консоли).

1. Откройте CRM → **Ещё → Настройки → Доступ** и скопируйте свой **UID**.
2. Firebase Console → Firestore Database → **Start collection** → ID коллекции `users`:
   - Document ID: ваш UID
   - поле `role` (string) = `owner`
3. Для каждого сотрудника: Authentication → Add user (email + пароль), скопируйте его UID
   и создайте документ `users/{UID}` с `role` = `manager`.
4. Firestore Database → вкладка **Rules** → вставьте содержимое `firestore.rules` → **Publish**.

Что может менеджер: клиенты, сделки, платежи, скидки, отсрочки, касса, WhatsApp-напоминания.
Что не может: удалять что-либо, править и отменять проведённые платежи, видеть инвесторов, историю действий и корзину, менять настройки.

## 2. Корзина

Всё, что удаляется в CRM (сделки, платежи, операции кассы, счета, инвесторы), сначала копируется
в коллекцию `trash`: кто удалил, когда и полное содержимое. Посмотреть: **Настройки → Корзина**.
Удалить или изменить записи корзины и истории действий не может никто, даже владелец из CRM.

## 3. Сверка касс

**Настройки → Сверка касс** пересчитывает остаток каждого счёта по операциям кассы.
Если есть расхождение, скорее всего на счёт когда-то внесли стартовый остаток не через кассу.
Проведите его операцией или нажмите «Разница …», чтобы привести остаток к операциям.

## 4. WhatsApp

Кнопки WhatsApp есть в «Контроле платежей», в карточке сделки и в дашборде («Крупнейшие просрочки»).
Кнопка открывает чат клиента с готовым текстом, остаётся нажать «Отправить».
Тексты меняются в **Настройки → Шаблоны WhatsApp**. Дата последнего напоминания видна в «Контроле платежей».

## 5. Ключ сервисного аккаунта (нужен для бэкапа и Telegram)

1. Firebase Console → ⚙️ Project settings → **Service accounts** → **Generate new private key**. Скачается JSON.
2. GitHub → репозиторий → Settings → Secrets and variables → Actions → **New repository secret**:
   - `FIREBASE_SERVICE_ACCOUNT`: всё содержимое JSON-файла.

Ключ даёт полный доступ к базе: никому его не пересылайте и не кладите в репозиторий.

## 6. Ежедневный бэкап

Workflow `.github/workflows/backup.yml` каждую ночь (~03:00 МСК) выгружает всю базу, шифрует её и хранит 90 дней
во вкладке **Actions → Бэкап базы → Artifacts**.

- Добавьте секрет `BACKUP_PASSWORD`: придумайте длинный пароль и сохраните его отдельно.
- Проверка: Actions → Бэкап базы → **Run workflow**.
- Расшифровка скачанного файла:
  ```
  openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in amana-crm-ДАТА.json.gz.enc -out backup.json.gz
  gunzip backup.json.gz
  ```

## 7. Утренняя сводка в Telegram

Каждый день ~09:00 МСК бот присылает: кто платит сегодня, ближайшие 3 дня, просрочку и крупнейших должников,
вчерашние поступления и остатки касс.

1. В Telegram откройте **@BotFather** → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`. Это ваш chat id.
   Для группы добавьте бота в группу; id группы начинается с `-`.
3. Добавьте секреты `TG_BOT_TOKEN` и `TG_CHAT_ID` (несколько получателей через запятую).
4. Проверка: Actions → Сводка в Telegram → **Run workflow**.
